## 1. 结构（Structural）

### 类型

交互设计方法论 / 数字产品与复杂系统设计实操框架。

### 一句话主旨

《交互设计精髓》强调以用户目标为中心，通过研究、人物模型、场景、交互框架和界面行为原则来设计产品行为，而不是堆砌功能或美化界面。

### 骨架（主要论点及其关系）

1. **用户目标优先**：产品设计首先要理解用户真正想完成什么，而不是从技术功能清单出发。
2. **研究转化为模型**：用户研究的价值在于形成可指导决策的人物模型，而不是停留在资料收集。
3. **场景推导行为**：场景把用户目标、环境限制、任务步骤和产品反馈连接起来。
4. **框架先于界面细节**：交互框架决定对象关系、信息架构、导航和工作流。
5. **界面行为降低负担**：界面应贴近心智模型，减少认知摩擦，提供反馈、一致性和容错。
6. **设计需要迭代验证**：原型和测试用于发现目标、流程与行为设计中的断点。

**论点之间的关系**：递进关系。先理解用户目标，再建模用户与场景，随后推导产品结构与界面行为，最后通过测试迭代。

### 作者要解决的核心问题

复杂产品为什么经常功能很多却不好用？如何从用户目标出发，把产品设计成能被理解、能被控制、能帮助用户完成任务的行为系统？

## 2. 解释（Interpretive）

### 关键术语（复习版解释，待原文校准）

| 术语 | 复习版解释 | 和常识用法的差异 |
|---|---|---|
| 目标导向设计 | 从用户目标推导功能、流程和产品行为的方法 | 不是“满足所有需求”，而是识别真正稳定的目标 |
| Persona / 人物模型 | 基于研究抽象出的典型用户 | 不是营销画像，也不是人口统计标签 |
| Scenario / 场景 | 用户在特定情境中完成目标的过程 | 不是故事润色，而是设计推导工具 |
| 心智模型 | 用户以为系统如何工作的理解 | 不等于系统真实实现方式 |
| 认知摩擦 | 用户理解、判断和操作时遇到的心理阻力 | 不只是步骤多，也包括不一致、不可预期和状态不清 |
| 交互框架 | 产品对象、导航、流程、命令和状态的总体组织 | 不等同于视觉稿或单页布局 |

### 核心命题（用自己的话）

1. 好产品不是功能最多，而是最能帮助目标用户完成关键目标。
2. 用户研究必须转化为人物模型和场景，才会进入真实设计决策。
3. 交互设计的对象是“产品行为”，界面只是行为被感知和操作的表层。
4. 工业设计中的智能产品和服务系统，也需要用交互逻辑组织任务流程、反馈和容错。

### 论证链

用户目标比功能需求更稳定 → 研究用户行为与动机 → 建立人物模型 → 构建典型场景 → 推导任务流程与交互框架 → 用界面原则降低认知摩擦 → 通过原型测试迭代。

## 3. 批判（Critical）★

### 作者的时代局限

- 书中大量方法来自数字产品和复杂软件语境，迁移到工业设计时需要补充材料、结构、制造、安全规范等实体产品约束。
- 若只按方法流程答题，容易忽略中国考研 337 对设计史、设计学和工业设计基础理论的综合考察。
- 交互技术快速变化，语音交互、AI Agent、多模态交互和无屏交互需要结合新案例扩展。

### 作者的立场盲点

- 方法论偏向专业团队工作流；个人备考需要把它压缩成答题模板和案例库。
- 强调目标和任务可能导致对情感体验、文化意义、审美象征的讨论不足。

### 未被证明的假设

- 假设用户目标可通过研究被稳定识别。
- 假设人物模型能代表足够多的真实使用差异。
- 假设设计团队有资源完成充分研究、原型和测试。

### 最强反对意见

在真实工业设计项目中，材料成本、生产工艺、品牌策略、供应链和安全法规可能比交互方法更先约束方案，因此不能把目标导向设计当成唯一答案。
